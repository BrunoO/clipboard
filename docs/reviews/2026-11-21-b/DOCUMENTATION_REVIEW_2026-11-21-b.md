**D1 — `docs/SECURITY_LESSONS.md` and `README.md` do not reflect the Linux outgoing concealed-marker limitation**  
- **Document / section**: `docs/SECURITY_LESSONS.md` → "3. Clipboard Privacy & OS Boundaries", and `README.md` → "Known Limitations".  
- **Severity**: Medium  
- **Evidence**:
  - `docs/SECURITY_LESSONS.md:26-28`:
    ```markdown
    - **Honor and emit OS concealed-clipboard markers on every platform:**
      - **Incoming (ignore password managers):** macOS `NSPasteboard` (`ConcealedType`, `AutoGeneratedType`, `TransientType`, `1Password`), Windows (`ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`, `CanIncludeInClipboardHistory == 0`), Linux X11 (`x-kde-passwordManagerHint` in `TARGETS`).
      - **Outgoing (protect copied secrets):** Re-attach OS concealed/no-history/no-cloud-sync markers immediately after writing a secret to the clipboard, schedule auto-clear, and clear any pending secret on application `Drop`.
    ```
  - `src/platform/mod.rs:303-329`:
    ```rust
    pub(crate) enum ConcealedMarkerSupport {
        /// Incoming markers are detected and outgoing secrets are marked natively.
        DetectAndEmit,
        /// Incoming markers are detected, but outgoing secrets cannot be marked natively.
        DetectOnly,
    }

    /// Returns the platform's concealed-marker capability.
    #[must_use]
    pub(crate) const fn concealed_marker_support() -> ConcealedMarkerSupport {
        if cfg!(any(target_os = "macos", target_os = "windows")) {
            ConcealedMarkerSupport::DetectAndEmit
        } else {
            ConcealedMarkerSupport::DetectOnly
        }
    }

    /// Returns a user-facing explanation when native marker emission is unavailable.
    #[must_use]
    pub(crate) const fn concealed_marker_limitation() -> Option<&'static str> {
        match concealed_marker_support() {
            ConcealedMarkerSupport::DetectAndEmit => None,
            ConcealedMarkerSupport::DetectOnly => Some(
                "Concealed clipboard items from other apps are detected, but this platform cannot advertise the same marker for secrets CipherClipboard copies. Copied secrets are still masked and auto-cleared.",
            ),
        }
    }
    ```
  - `src/platform/linux.rs:234-243`:
    ```rust
    /// Marker emission is intentionally unavailable on Linux/X11.
    ///
    /// `arboard` owns the `CLIPBOARD` selection when a secret is copied, so adding
    /// `x-kde-passwordManagerHint` would require taking ownership and proxying every
    /// requested target. Detection remains available via [`is_clipboard_concealed`],
    /// and the UI discloses this limitation.
    pub(super) fn mark_clipboard_concealed() {
        #[cfg(test)]
        MARK_CALLED.store(true, Ordering::Release);
    }
    ```
  - `README.md:178-183` ("Known Limitations") lists monochrome emojis, Windows UIPI, and Windows `Alt+Space`, with no mention of Linux concealed-marker emission or pure Wayland limitations.
- **Drift**: Commit `7ce5fef` ("fix(platform): make Linux concealed-marker gap explicit") documented in code and in the Settings UI (`src/app/settings_view.rs:471-478`) that Linux only detects incoming `x-kde-passwordManagerHint` (`ConcealedMarkerSupport::DetectOnly`) and cannot emit outgoing concealed markers without replacing `arboard`'s X11 selection owner. However, `docs/SECURITY_LESSONS.md:26-28` still states "Honor and emit OS concealed-clipboard markers on every platform", and `README.md` "Known Limitations" omits this Linux privacy limitation (as well as pure Wayland limitations for global hotkeys/synthetic paste).
- **Impact**: Security reviewers and Linux users reading `README.md` or `docs/SECURITY_LESSONS.md` are led to believe outgoing secrets on Linux carry `x-kde-passwordManagerHint` protection against third-party clipboard monitors, whereas only incoming detection and in-app auto-clear apply on Linux.
- **Recommendation**: Update `docs/SECURITY_LESSONS.md:26-28` to state that outgoing OS concealed markers are emitted on macOS and Windows while Linux is `DetectOnly` (disclosed via `platform::concealed_marker_limitation()`), and add a Linux/X11 & Wayland bullet under `README.md` → "Known Limitations" covering `DetectOnly` concealed-marker support and pure Wayland global-hotkey/auto-paste limitations.
