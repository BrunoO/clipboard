# Security Lessons Learned

Distilled from the CipherClipboard security & cross-platform hardening reviews. Future contributors and coding agents should treat these as concrete invariants when modifying this codebase (or similar desktop security tools).

---

## 1. Key Management & In-Memory Secret Hygiene

- **Prefer the OS Keyring; fail closed when an encrypted DB already exists.** Never silently generate a new encryption key if `clipboard_history.db` is already on disk — that corrupts/locks out user data. Return an actionable, OS-appropriate recovery error instead (`src/crypto.rs`).
- **Make fallbacks visible, never silent.** If the OS Keyring is unavailable and a local `.encryption_key` fallback is used, surface that degraded state explicitly in the UI (`KeyStorageMode::LocalFileFallback`).
- **Protect fallback key files cryptographically and with restrictive permissions.** On Unix, use `OpenOptionsExt::mode(0o600)` at creation time (and `0o700` on the data directory) rather than `fs::write` followed by `chmod`. On Windows, encrypt fallback `.encryption_key` files with user-scoped DPAPI (`CryptProtectData` / `CryptUnprotectData` with `CRYPTPROTECT_UI_FORBIDDEN` and application entropy, zeroizing OS-allocated plaintext buffers before `LocalFree`) before writing to disk, and also tighten ACLs via `%SystemRoot%\System32\icacls.exe` with `USERDOMAIN\USERNAME` and `CREATE_NO_WINDOW`.
- **Zeroize secrets in memory.** Wrap encryption keys, pending clipboard secrets, generated passwords, and transient skip buffers in `zeroize::Zeroizing<T>` so buffers are wiped on drop or replacement, and scope key lifetimes tightly (e.g., drop the DB key before entering the GUI loop).

## 2. Database & Deletion Hygiene

- **Enable `PRAGMA secure_delete = ON` on SQLite/SQLCipher** so deleted rows and pruned secrets are zero-overwritten on disk rather than left in free pages.
- **Compact and truncate WAL on full clear.** Deleting rows alone leaves plaintext/ciphertext history in the WAL journal and freelist; run `VACUUM;` and `PRAGMA wal_checkpoint(TRUNCATE);` in `Database::clear()`.
- **Escape `LIKE` wildcards and exclude secrets from search.** Always escape `\`, `%`, and `_` with `ESCAPE '\'` in parameterized `LIKE` queries, and filter `WHERE kind != 'secret'` so search cannot be used as an oracle to probe masked secrets.

## 3. Clipboard Privacy & OS Boundaries

- **Honor and emit OS concealed-clipboard markers on every platform:**
  - **Incoming (ignore password managers):** macOS `NSPasteboard` (`ConcealedType`, `AutoGeneratedType`, `TransientType`, `1Password`), Windows (`ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`, `CanIncludeInClipboardHistory == 0`), Linux X11 (`x-kde-passwordManagerHint` in `TARGETS`).
  - **Outgoing (protect copied secrets):** Re-attach OS concealed/no-history/no-cloud-sync markers immediately after writing a secret to the clipboard, schedule auto-clear, and clear any pending secret on application `Drop`.
- **Verify foreground ownership before synthetic input (auto-paste).** Never inject `Ctrl+V` / `Cmd+V` blindly after a sleep delay; verify the previously captured window/PID is actually foreground on macOS, Windows, and Linux.
- **Respect Windows UIPI.** Detect when the target window runs at a higher mandatory integrity level (e.g., Administrator) using a properly aligned buffer (`#[repr(C, align(8))]`, 256 bytes for `TOKEN_MANDATORY_LABEL` + inline SID) and **fail closed** when `TOKEN_QUERY` is denied — warn the user to paste manually instead of letting Windows silently drop injected keystrokes.

## 4. Platform FFI, `unsafe`, & Window Lifecycle Safety

- **Isolate `unsafe` behind crate-wide `#![deny(unsafe_code)]`.** Allow `unsafe_code` only in the OS FFI backend modules (`src/platform/macos.rs` and `src/platform/windows.rs`), keeping `src/platform/mod.rs`, `src/platform/linux.rs`, and all application/UI/DB logic 100% safe Rust.
- **Never mutate private OS windows or call AppKit re-entrantly.** On macOS, `[NSApplication windows]` includes AppKit's private internal windows (Touch Bar panels, tooltips, popovers). Filter with `canBecomeMainWindow` before ordering front, guard `NSApplication` calls with `is_main_thread()`, wrap ObjC allocations in `objc::rc::autoreleasepool`, and defer window ordering out of `NSNotificationCenter` callbacks to avoid `_NSTouchBarFinderObservation` KVO crashes.
- **Quit on macOS by exiting the process after cleanup.** A normal `Close` lets AppKit run one more display-cycle flush against a destroyed `WinitView`, crashing with `NSRangeException` (`_NSTouchBarFinderObservation`). Keep the macOS `ClipboardApp::on_exit` → `process::exit(0)` path, and keep the CI job `macOS quit smoke test` (debug-only `CIPHERCLIPBOARD_SMOKE_QUIT_MS` hook) green. See `docs/MULTIPLATFORM_LESSONS.md` §3.
- **Use checked integer conversions and explicit raw pointers (`&raw mut`) at FFI boundaries** to prevent truncation, sign-loss, and alignment UB.

## 5. Input Validation, Media Decoding, & External Launchers

- **Allow-list URL schemes before launching a browser.** Parse and normalize with `url::Url::parse`, permitting only `http` and `https` with a non-empty host (`sanitize_browser_url`). Never pass raw clipboard strings to `webbrowser::open` (blocks `file://`, `javascript:`, `ms-msdt:`, and CLI flag injection).
- **Guard image decoders against decompression bombs *before* allocation.** Inspect PNG header dimensions first (`<= 40 MP`) and configure `image::Limits::max_alloc` before calling `.decode()`.
- **Never log clipboard contents or secrets in release builds.** Gate preview prints with `#[cfg(debug_assertions)]` (still redacting detected secrets), create `app.log` with `0600` permissions inside the `0700` data dir, and rotate logs at a fixed cap (1 MiB).

---

## 6. Supply Chain, CI/CD, & Static Analysis Guardrails

- **Pin every GitHub Action to a full commit SHA** and scope `permissions:` to least-privilege (`contents: read` at workflow level; `write` only on jobs that actually publish releases/attestations).
- **Never silently skip security/quality gates.** Remove `continue-on-error` on platform test jobs, run `cargo clippy --all-targets --all-features -- -D warnings` on **all** target OSes (Linux, macOS, Windows), and fail loudly if `SONAR_TOKEN` is missing on `push` to `main`.
- **Verify third-party release dependencies end-to-end:**
  - Verify Microsoft Authenticode signatures on downloaded `vc_redist.x64.exe`.
  - Derive the exact linked OpenSSL runtime DLL name (`libcrypto-*-x64.dll`) from `libcrypto.lib` and assert the compiled `.exe` actually imports the staged DLL.
  - Publish SHA-256 checksums (using `--` before globs in shell scripts) and SLSA build provenance attestations (`actions/attest-build-provenance`).
- **Enforce `cargo-deny`** with `wildcards = "deny"`, `unknown-registry = "deny"`, and `unknown-git = "deny"`, and avoid static secret literals in unit tests (construct test fixtures dynamically so secret scanners don't mask real leaks behind false positives).
